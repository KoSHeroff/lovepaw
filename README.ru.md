# LovePaw

![Build](https://github.com/KoSHeroff/lovepaw/actions/workflows/build.yml/badge.svg)

Косметические питомцы, которые ходят рядом с тобой. Питомец — это **данные, а не сущность**:
он описан файлами в ресурспаке, а считается и рисуется на клиенте. Поэтому мод работает на
любом сервере, включая ванильный, — там питомца видишь только ты.

Поставь мод ещё и на сервер — и питомцев увидят все.

- **Fabric и NeoForge**, Minecraft 1.21.1 (новые версии добавляются одной строкой в сборке)
- Питомцы делаются в **Blockbench** и лежат обычным JSON — без кода и компиляции
- Без внешних зависимостей: поддержка Bedrock-моделей, анимаций и Molang написана внутри мода

Формат питомца: [docs/pet-format.md](docs/pet-format.md).

## Как это устроено

Питомец не является сущностью Minecraft. Ничего не регистрируется, не спавнится и не
сохраняется в мире.

| | Мод только на клиенте | Мод на клиенте и сервере |
|---|---|---|
| Ты видишь своего питомца | да | да |
| Другие видят твоего питомца | нет | да |
| Нагрузка на сервер | нет | один маленький пакет на смену питомца |

Сервер никогда не шлёт координаты — только «у кого какой питомец». Поведение считает каждый
клиент сам. Поэтому это дёшево и поэтому клиентская часть работает даже там, где о моде
никогда не слышали.

Если у игрока питомец, которого у тебя нет, ты просто ничего не увидишь. Ровно в этом месте
потом встроится каталог с автоматической загрузкой.

## Как пользоваться

- **G** — меню питомцев (переназначается в управлении; P занята ванильным «социальным
  взаимодействием», поэтому по умолчанию не она)
- Выбери питомца или «Без питомца», чтобы убрать
- Там же переключается, видишь ли ты чужих питомцев

Питомец живёт не на поводке, а в своей зоне. Пока ты не уходишь далеко от места, где
остановился, он тебя вообще не замечает и занимается своими делами: гуляет по точкам,
которые выбирает сам, осматривается, садится. Уйдёшь за границу зоны — он не бежит следом,
а прикидывает, куда ты направляешься, и бежит в зону вокруг этой точки, оказываясь рядом с
тобой, а не в хвосте. Размер зоны, насколько далеко вперёд он целится и как часто садится
— настройки конкретного питомца, см. [docs/pet-format.md](docs/pet-format.md).

Кнопка **«Настройки»** в меню крутит твоего питомца слайдерами вживую: зона, из которой
можно выйти, упреждение движения, радиус прогулок, как часто садится, размер и нужны ли
прогулки вообще. Мир за экраном не ставится на паузу — каждое изменение видно сразу.
«Вернуть настройки питомца» сбрасывает всё.

Эти правки лежат в `config/lovepaw-client.json` рядом с выбором питомца:

```json
{
  "selected_pet": "lovepaw:cat",
  "show_other_players_pets": true,
  "overrides": {
    "anchor_radius": 5.0,
    "prediction_seconds": 1.2,
    "wander_radius": 4.5,
    "sit_chance": 0.35,
    "wander": true,
    "scale": 1.0
  }
}
```

Всё, чего в `overrides` нет, остаётся на усмотрение питомца — в этом и смысл: значения
автора пака работают, пока ты сам не решил иначе. Правки действуют только на твоего
питомца; у чужих остаются настройки их паков.

Серверные — `config/lovepaw-server.json`:

```json
{
  "share_with_others": true,
  "allowed_pets": [],
  "denied_pets": []
}
```

`share_with_others: false` — питомцев видит только владелец. Пустой `allowed_pets` означает
«всё, чего нет в `denied_pets`».

## Как добавить питомца

Положить папку в `lovepaw/pets/` в каталоге игры — мод создаёт её при первом запуске:

```
.minecraft/lovepaw/pets/<имя_питомца>/
    pet.json
    model.geo.json
    texture.png
    animations.animation.json
```

Перезагрузи ресурсы (F3 + T) — питомец появится в меню под идентификатором
`local:<имя_питомца>`. Ни пака, ни неймспейса: экспортируешь из Blockbench прямо в папку и
жмёшь клавишу.

Та же папка внутри ресурспака, по пути `assets/<неймспейс>/lovepaw/pets/<имя_питомца>/`, —
это способ отдать питомца другим; тогда идентификатор будет `неймспейс:имя_питомца`. Полное
описание формата и экспорт из Blockbench: [docs/pet-format.md](docs/pet-format.md).

## Сборка

```bash
./gradlew build                      # все цели
./gradlew :1.21.1-fabric:build       # одна цель
./gradlew :1.21.1-fabric:runClient   # клиент для отладки
./gradlew :1.21.1-fabric:test        # тесты парсеров
```

Готовые jar-файлы — в `versions/<цель>/build/libs/`.

Цели перечислены в `settings.gradle`, версии их зависимостей — в
`versions/<цель>/gradle.properties`. Добавить, например, 1.21.11 — это по строке в каждом.
[Stonecutter](https://stonecutter.kikugie.dev/) держит один общий исходник на все цели; оба
лоадера собираются на Mojang-маппингах, поэтому в общем коде не нужны подмены имён.

Структура исходников:

```
src/main/java       общий код (модель, анимация, поведение, рендер, протокол)
src/fabric/java     точки входа Fabric
src/neoforge/java   точки входа NeoForge
src/main/resources  метаданные мода, языки, встроенные питомцы
src/test/java       тесты парсеров и конверсии координат
```

## API для аддонов

Пока не опубликован — намеренно. Сейчас поддерживаемый способ добавить питомца это JSON, и
только его можно будет раздавать по сети. Внутри всё сведено к одной точке регистрации,
поэтому Java API откроется позже без переписывания, но до публикации стабильного API нет.

## Состояние

Работает: загрузка питомцев из паков и из собственной папки игрока, Bedrock-модели и анимации с Molang, поведение
следования с самостоятельными прогулками, любопытством к окружающему и сидением, коллизии,
шаг на блок, прыжок через препятствие и обход того, что не перепрыгнуть, плавание, меню
выбора, клиентский рендер с тенью, ретрансляция на сервере для обоих лоадеров.

Ещё нет: каталога с загрузкой, звуков, эффектов из ключевых кадров, поворота UV на грани,
опубликованного Java API.

Отладочный клиент стартует чисто: встроенные питомцы загружаются, рукопожатие с сервером
проходит. Парсеры, конверсия координат и поведение покрыты тестами. Чего тест проверить не
может — как питомец выглядит на экране; эти мелочи вылезут в игре.
